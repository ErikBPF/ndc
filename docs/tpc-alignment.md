# TPC-H and TPC-DS alignment

NDC reuses TPC-H data and selected query ideas, and draws workflow and analytical
inspiration from TPC-DS. Alignment means preserving those stated inspirations and
correctness discipline; it does not mean implementing either complete benchmark.

| Concern | TPC-H | TPC-DS | NDC |
|---|---|---|---|
| Data | Eight relational entities generated by dbgen | Retail dimensional schema generated by dsdgen | TPC-H entities, derived nested/depth layouts, separate synthetic shapes |
| Workload | 22 queries and RF1/RF2 | 99 query templates and data maintenance | 24 historical variants in `tpch`; 46 total workloads, including two DS-inspired analytics |
| Parameters | qgen substitution parameters | dsqgen template bindings | Fixed SQL; query seed changes order, data seed changes synthetic fixtures |
| Execution | Power and throughput with refresh operations | Load, power, two throughput and two maintenance phases | Explicit measurement phases, without the prescribed TPC sequence or refresh protocol |
| Validation | Specified qualification and audit requirements | Specified qualification and audit requirements | NDC pins, independent references and complete-result checks; no TPC audit |
| Results | Defined TPC performance/price metrics | Defined TPC performance/price metrics | Per-query samples and descriptive totals; no TPC score |

Sources: [TPC-H 3.0.1, clauses 2, 4 and 5](https://www.tpc.org/tpc_documents_current_versions/pdf/tpc-h_v3.0.1.pdf)
and [TPC-DS 4.0.0, clauses 3–5 and 7](https://www.tpc.org/tpc_documents_current_versions/pdf/tpc-ds_v4.0.0.pdf).

`SUITE=tpch` names NDC’s historical query membership, not the full official 22-query
TPC-H suite. NDC append/update/delete/compaction cases are not RF1/RF2 or TPC-DS
refresh sets. Renaming them to official phase names would overstate compatibility.

## What SF1 validates

SF1 controls the TPC-H base data: 1,500,000 orders and 6,001,215 line items, plus
the other six entities. NDC checks these counts in [sizes.csv](../ndc/sizes.csv).
Nested and table-format copies have different physical sizes. Synthetic shape
cardinality still comes from `PARENTS`, `FANOUT` and `WIDTH`; it does not scale
implicitly with SF1. Tiny answer pins are not reused as SF1 answers: the larger
scale uses equivalent reference queries.

SF1 can expose scan, projection, nested computation and resource-limit defects.
It does not establish TPC compliance, performance significance, deletion-vector
coverage or execution of a particular native operator. PR validation must pair
answer checks with the relevant upstream regression and plan assertions.

## Review priorities

Preserve workload semantics, exact validation and reproducibility before adding
more queries. Keep engine-specific execution and diagnostics separate from the
benchmark contract. Broader query parameterization and engine-neutral reporting
remain explicit extensions, not prerequisites for claiming an NDC correctness run.
